# 费用规则与退费结算设计修订

## 1. 修订目的与适用范围

退费是少数机房才需要的特殊业务能力，当前仅广发台存在该需求。原设计中将“退费管理”作为常驻菜单，并将法定节假日与费用标准合并维护，不利于适配不同机房的业务差异。

本修订适用于所有机房，目标是：

- 法定节假日作为系统级独立能力维护和计算；
- 餐补、节假日加班费及退费规则按机房配置、按需启用；
- 仅在当前机房启用退费规则时提供退费结算能力；
- 以最终实际值班人员为口径，生成可审计、收支平衡的人员间结算结果。

本文件中与 `01-需求分析.md`、`02-原型设计.md`、`03-总体设计.md`、`04-开发实施计划.md`、`05-排班规则设计.md`、`06-设计修订.md` 存在冲突的内容，以本文件为准。

## 2. 业务边界

### 2.1 法定节假日

法定节假日是系统级全局日历，与台站、机房、费用规则和退费业务解耦。其用途包括：

- 请假等业务的法定节假日校验；
- 判断节假日加班费及其退费规则是否适用；
- 排班、考勤、报表中的节假日标记。

系统只维护“法定节假日本身”，不维护放假调休、补班、连休或补休安排。

### 2.2 机房费用规则

费用规则属于机房配置，而不是系统全局配置。不同机房可启用不同费用项目、金额标准和退费规则。

首期支持以下费用项目：

| 费用项目 | 可配置内容 |
| --- | --- |
| 餐补 | 是否启用；各班次的补贴标准；是否启用退费；退费规则 |
| 节假日加班费 | 是否启用；每人每班标准；是否启用退费；退费规则 |

规则状态和行为如下：

- 未启用费用项目：不参与费用或退费计算，也不显示该项目的退费配置；
- 已启用费用项目、未启用退费：仅维护费用标准，不产生人员间退费；
- 已启用退费：必须至少存在一条完整且启用的退费规则；
- 节假日加班费退费仅在法定节假日班次适用。

### 2.3 退费结算

退费结算是由机房费用规则驱动的按需功能，不是所有机房都应显示的常驻模块。系统不处理真实资金支付，也不记录微信群红包的完成状态；系统产出结算明细和汇总表，供人员在线下或微信群内完成支付。

## 3. 法定节假日设计

### 3.1 自动推算规则

系统按年度自动推算下列法定节假日：

| 节日 | 推算规则 |
| --- | --- |
| 元旦 | 公历 1 月 1 日 |
| 春节 | 农历除夕、正月初一至初三 |
| 清明节 | 二十四节气中的清明当日 |
| 劳动节 | 公历 5 月 1 日至 2 日 |
| 端午节 | 农历五月初五 |
| 中秋节 | 农历八月十五 |
| 国庆节 | 公历 10 月 1 日至 3 日 |

同一天命中多个节日时，日历记录按日期去重，并保留全部节日名称或合并说明。农历与节气换算应使用经过验证、支持目标年份范围的日历库。

### 3.2 年度预览与人工修订

管理员可预览某年度自动推算结果。自动生成结果不是日常人工维护对象，但必须保留年度级或日期级人工修订能力，以应对法规变化、算法问题或历史数据修正。

每条节假日记录应至少保存：日期、名称、是否法定、来源（`system_calculated` / `manual_override`）、修订原因、创建与更新时间。

人工修订不应影响其他年度的推算规则。涉及已生成费用、退费或考勤结果时，按既有“需重新生成”联动规则处理。

### 3.3 页面与权限

“法定节假日”应为系统级独立页面，不依赖当前机房上下文。页面提供年度选择、自动生成/预览、查询和人工修订入口。权限按全局节假日维护权限控制。

## 4. 机房费用规则设计

### 4.1 页面结构

原“节假日与标准”页面拆分为：

- **法定节假日**：系统级页面，见第 3 章；
- **费用规则**：机房级页面，随当前机房上下文切换。

“费用规则”页按费用项目展示配置卡片或 Tab。每个项目先设置是否启用；启用后显示金额标准；开启退费后再显示退费规则列表。

### 4.2 退费规则字段

每条退费规则至少包括：

| 字段 | 说明 |
| --- | --- |
| 费用项目 | 餐补或节假日加班费 |
| 是否启用 | 控制是否参与后续结算 |
| 付款班次 | 实际值班人员承担付款义务的班次 |
| 收款班次 | 实际值班人员享有收款权益的班次 |
| 每名付款人退费标准 | 单位为元/人/班，按分保存 |
| 适用条件 | 餐补默认不限；节假日加班费默认仅法定节假日 |
| 生效区间 | 可选，按值班日期匹配，供未来标准调整和历史追溯 |

同一机房内，费用项目、付款班次、收款班次和适用条件相同的启用规则，其生效区间不得重叠。生效起止日期均包含在区间内；未填写起止日期表示无边界。计算时按值班日期选择唯一有效规则，批次必须保存所用规则快照，后续修改规则不得改变已生成批次的历史口径。

首期可为广发台预置以下规则：

| 费用项目 | 付款班次 | 收款班次 | 每名付款人退费标准 | 条件 |
| --- | --- | --- | --- |
| 餐补 | 晚班 | 中班 | 4 元/人/班 | 无 |
| 节假日加班费 | 晚班 | 中班 | 56 元/人/班 | 仅法定节假日 |

## 5. 退费计算口径

### 5.1 数据来源

退费计算以指定月份、指定机房的最终实际值班人员为唯一口径。换班、请假、顶班和历史修正生效后形成的最终人员均参与计算；不以原始排班人员或变更台账作为计算主表。

每个退费批次的范围为“机房 + 月份 + 本次选择的费用项目/规则集合”。计算前由用户在当前机房已启用的费用项目中选择餐补、节假日加班费或全部；批次保存实际参与计算的规则清单和快照。相同机房、月份和规则集合重新计算时更新原批次，不因重复操作产生重复结算；不同规则集合可分别保留独立批次。

### 5.2 班次集合分摊

每条规则按付款班次与收款班次的实际人员集合计算，不按岗位序号或个人一对一配对：

```text
总退费 = 付款班次实际人数 × 每名付款人退费标准
每名付款人应退 = 每名付款人退费标准
每名收款人应收 = 总退费 ÷ 收款班次实际人数
```

例如，晚班实际 2 人、中班实际 3 人、每名晚班人员应退 4 元时：

```text
总退费 = 2 × 4 = 8 元
每名晚班人员应退 = 4 元
每名中班人员应收 = 8 ÷ 3 元
```

### 5.3 金额精度与尾差

金额以“分”为最小存储和计算单位。收款人均分后不能整除的尾差，按收款人员的固定、可复现排序依次分配 1 分，直至分配完毕。

例如 8 元由 3 名收款人均分，按固定排序生成 `2.67 元、2.67 元、2.66 元`。任何批次必须满足：

```text
全部付款明细金额之和 = 全部收款明细金额之和 = 总退费
```

### 5.4 异常处理

付款班次或收款班次没有实际人员时，不能生成该条规则的正常结算明细。系统应将其列为计算异常，显示日期、班次、规则和缺失人员情况；异常不得被静默忽略。

计算可保留其他正常规则实例的结果，供用户核查；但批次存在未处理计算异常时，禁止复核、锁定和导出。处理源数据后必须重新计算，异常清零后才能进入后续流程。

## 6. 退费结算交互

### 6.1 入口可见性

满足以下条件时，当前机房显示“退费结算”入口：

1. 当前机房至少存在一条完整且启用的退费规则；
2. 当前用户具备退费批次管理或退费结果查看权限。

没有启用退费规则的机房不显示该入口。用户直接访问时，应提示“当前机房未启用退费规则”，而不是展示空页面。

系统管理员切换机房后，费用规则、入口可见性和结算数据同步切换。普通账号固定使用绑定人员所属机房。

绑定有效人员的普通账号不进入“退费结算”管理页；其个人结果通过独立的“我的费用/我的退费”入口查看。

### 6.2 结算页流程

```text
选择月份
→ 自动识别当前机房已启用的退费规则
→ 计算
→ 查看明细与人员汇总
→ 复核
→ 锁定
→ 导出红包结算表
```

页面顶部提供月份选择及操作按钮。退费类型只能显示当前机房已启用的项目；未启用项目不得作为可选条件或空批次生成对象。

页面主体包括：

- 批次状态卡片：批次号、月份、适用规则、总额、计算时间、异常数与状态；
- 明细表：费用项目、日期、人员、收支方向（应退/应收）、金额、所属班次、对方班次、规则与来源；不记录付款人与收款人的个人一对一配对；
- 人员汇总表：人员、应退、应收、净付/净收，可下钻查看明细；
- 异常清单：无法结算的规则实例及原因。

导出文件命名为“红包结算表”，至少包含逐笔收付明细和人员净额汇总。

### 6.3 批次生命周期

```text
未计算 → 已计算 → 已复核 → 已锁定 → 已导出
已计算 / 已复核 → 重新计算
```

锁定后禁止普通重新计算。批次锁定仅属于退费结算自身的生命周期，不冻结排班、换班、请假或顶班业务。

历史修正影响已经生成的退费结果时，相关批次标记为“需重新结算”；该状态下禁止导出，必须重新计算后才能继续复核、锁定或导出。

## 7. 权限与个人结果

- 具备退费批次管理权限的账号可计算、重新计算、复核、锁定和导出当前机房的退费批次；
- 具备退费结果查看权限的账号可查看当前机房全量明细和汇总；
- 绑定有效人员的普通账号无需退费管理功能权限，也可通过“我的费用/我的退费”查看本人应退、应收与净额；
- 个人结果接口只能返回本人记录；无有效人员绑定时拒绝访问。

## 8. 数据模型调整建议

在原 `refund_standard` 的基础上，后续应拆分或扩展为以下逻辑实体：

| 实体 | 作用 |
| --- | --- |
| holiday_calendar | 系统级法定节假日，记录自动推算与人工修订来源 |
| fee_policy | 机房费用项目的启用状态、标准和生效区间 |
| refund_rule | 机房退费规则，包含付款/收款班次、单价、条件和启用状态 |
| refund_batch | 按机房、月份和规则集合生成的结算批次及生命周期状态 |
| refund_detail | 人员级应退或应收明细，以及关联规则、班次和来源 |

`refund_detail` 应能够区分付款与收款方向：每名付款人生成一笔应退明细，每名收款人生成一笔应收明细，不建立付款人与收款人的个人配对关系。明细与批次均应保存当次计算使用的规则快照、实际人数和金额，以保证后续标准变更后历史结果仍可追溯。
