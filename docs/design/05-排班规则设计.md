# 排班规则设计

## 1. 设计目标

删除"晚早组""中班组""槽位编号"等系统级硬概念。排班规则的核心逻辑改为：**管理员在 N 天 × M 班的表格中，直接为每个日期每个班次选择值机员**。M = 当前机房启用的班次数，表格列标题直接引用班次名称和时间。任何台站的排班规则都通过循环表格驱动，不写死特定算法。

---

## 2. 规则配置

管理员按机房配置排班规则。每个机房一套独立规则。

### 2.1 配置步骤

| 步骤 | 操作 |
|------|------|
| 1 | 设定循环天数 N |
| 2 | 设定起始日期（只能从明天起） |
| 3 | 系统生成 N 行 × M 列空表格，列标题来自 `shift_def` 的班次名称和时间，行首为真实日期 |
| 4 | 管理员在每个格子，从**当前机房值机员列表**中下拉选择人员 |
| 5 | 保存（草稿状态） |
| 6 | 发布（普通用户可见，可发起换班/请假） |

### 2.2 配置示例（以 3 班制为例）

广发台，6 天循环，3 班（早/中/晚），起始日期 7 月 17 日，每格 2 人：

|          | 早       | 中       | 晚       |
|----------|----------|----------|----------|
| 7月17日  | E1, E2   | B1, B2   | A1, A2   |
| 7月18日  | A1, A2   | B1, B2   | A1, A2   |
| 7月19日  | A1, A2   | D1, D2   | C1, C2   |
| 7月20日  | C1, C2   | D1, D2   | C1, C2   |
| 7月21日  | C1, C2   | B1, B2   | E1, E2   |
| 7月22日  | E1, E2   | B1, B2   | E1, E2   |

地球站，5 天循环，起始日期 7 月 17 日，每格 2 人：

|          | 早       | 中       | 晚       |
|----------|----------|----------|----------|
| 7月17日  | B1, B2   | A1, A2   | A1, A2   |
| 7月18日  | A1, A2   | C1, C2   | C1, C2   |
| 7月19日  | C1, C2   | D1, D2   | D1, D2   |
| 7月20日  | D1, D2   | E1, E2   | E1, E2   |
| 7月21日  | E1, E2   | B1, B2   | B1, B2   |

### 2.3 系统校验

- 每天每班都有人员填充
- 每格人数达标（每格人数按机房可配置，所有格子统一）
- 所选人员属于当前机房
- **不做：**同人连续出现限制

---

## 3. 排班生成

- 规则发布即生效：规则表 × 起始日 = 一条无限循环的排班序列
- 排班只生成一次，跨月自动延续
- 展示和报表导出按月切片

---

## 4. 规则变更

### 4.1 触发场景

| 场景 | 操作 |
|------|------|
| 人员永久调走/加入 | 修改格子中的人员选择 → 保存 → 重新发布 |
| 改循环天数 | 同上 |
| 改起始日 | 同上 |

### 4.2 重新发布机制

| 条件 | 行为 |
|------|------|
| 该人员有未完成的换班/请假/顶班 | **阻止**，提示先处理 |
| 该人员有已完成的换班记录 | 允许，换班记录保留 |
| 已锁定月份 | 不动 |
| 起始日期之前 | 不动 |
| 起始日期（含）起 | 新表生成 |
| 未来日期上已有换班/顶班 | 保持实际值班结果，格子占位覆盖 |

### 4.3 历史版本

- 每次保存生成**完整表格副本**，不存差异
- 多版本并存：历史月份按对应版本重建排班
- 排班管理员可手工调整已生成排班的个别日期，无需审批

---

## 5. 换班

| 项目 | 说明 |
|------|------|
| 发起方式 | 值机员本人，选择自己的具体日期班次 |
| 类型 | 单向替班或互相换班 |
| 限制 | 不限制"同格子"，任意两个值机员均可 |
| 流程 | 提交 → 对方确认 → 机房主任审批 → 生效 |
| 跨月 | 允许 |
| 撤回/作废 | 允许 |
| 生效后 | 实际值班记录更新，考勤和退费按实际值班人计算 |

---

## 6. 请假与顶班

### 6.1 请假

| 项目 | 说明 |
|------|------|
| 发起 | 值机员本人，选具体日期班次 |
| 类型 | 公休假、事假、病假，无需材料 |
| 限制 | 法定节假日班次禁止请假，无例外 |
| 审批 | 机房主任审批 |

### 6.2 顶班

| 项目 | 说明 |
|------|------|
| 触发 | 请假获批后，主任安排顶班 |
| 顶班人来源 | 检修班人员、机房主任、副主任（不限于排班表中人员） |
| 资格限制 | 无 |
| 确认 | 顶班人需确认，拒绝后主任重新安排 |
| 生效后 | 实际值班记录替换为顶班人 |
| 考勤影响 | 不影响顶班人的行政班考勤 |

---

## 7. 退费规则

仅广发台中波机房需要，按机房级别配置。

### 7.1 餐补标准

| 班次 | 金额 |
|------|------|
| 早班 | 10 元/人/班 |
| 中班 | 10 元/人/班 |
| 晚班 | 14 元/人/班 |

### 7.2 退费标准

| 类型 | 规则 | 金额 |
|------|------|------|
| 餐补退费 | 晚班人员退给中班人员 | 4 元/人/班 |
| 节假日加班费退费 | 晚班人员退给中班人员 | 56 元/人/班 |

计算公式：150 × 3 / 8 ≈ 56（中班承担 3 小时晚班工作，系统中无需体现具体时间段）。

### 7.3 计算依据

- 以实际值班记录为唯一计算口径（排班 + 换班 + 顶班合并后）
- 顶班人与值机员一样参与退费收付
- 退费标准首期固定，保留配置表支持后续可调整
- 退费方式为微信群红包，系统不接支付，不记录红包完成状态
- 输出：明细表 + 汇总表（Excel 导出）

---

## 8. 月度锁定

- 锁定某月后，该月及之前所有排班、换班、请假、顶班、退费、考勤不可修改
- 锁定前检查无未完成业务

---

## 9. 角色职责调整

| 角色 | 职责 |
|------|------|
| 系统管理员 | 预设排班规则模板（循环天数、每格人数） |
| 排班管理员 / 机房主任 | 配置规则表（填人选人）、发布、重新发布、个别日期调整、导出值班表 |
| 值机员 | 查看本人排班、发起换班、发起请假 |
| 机房主任 | 审批换班/请假、安排顶班 |

---

## 10. 日报切割规则

排班按日历日切割，不关心跨天连续性。

---

## 11. 删除的旧概念

| 旧概念 | 原因 |
|--------|------|
| 晚早组 / 中班组 | 只是格子里人员的排列外观，不是系统规则 |
| 槽位编号（1/2/3/4/5） | 直接填人名，不需要编号 |
| 槽位命名 | 不需要 |
| 每月重新生成排班 | 只生成一次，跨月循环延续 |
| 起始轮次 | 不存在，行首即日期 |
| 排班算法硬编码 | 改为循环读取表格，任何台站适用 |
| group_type 字段（night_early_group/middle_group） | 删除 |
