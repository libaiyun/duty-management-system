# 值班展示与变更台账设计修订

本文记录关于最终排班展示、值班变更台账、班次交互和历史修正的设计结论。后续相关开发、验收以本文为准；与既有设计冲突时，本文优先。

---

## 1. 核心口径

### 1.1 原始排班与最终排班

- **原始排班基线**：排班规则发布时生成的计划人员，用于追溯。例如：7 日原计划为 A。
- **最终排班**：换班、请假、顶班或历史修正生效后的最终责任人。例如：A 与 B 换班生效后，7 日最终人员为 B。
- 系统首期没有打卡或签到能力；最终排班表示业务调整后的责任人，不表示现实到岗证明。

排班表保存并展示最终排班；原始排班基线必须保留，不能因最终人员变更而丢失。

```text
原始排班基线：A
最终排班：B
值班变更台账：A → B、变更原因、业务单、审批/修正信息
```

### 1.2 计算口径

锁定后的历史最终排班是退费、考勤和报表的唯一计算口径。

- 换班、请假、顶班或历史修正生效后，直接更新最终排班；
- 退费、考勤、报表读取最终排班，不以值班变更台账作为计算主表；
- 既有 `actual_duty` 可在实施迁移期作为兼容查询层或逐步废弃，不再定义为独立的全量计算主表。

## 2. 排班表展示与交互

### 2.1 展示规则

1. 排班表是日常值班查看和业务发起的主入口，始终展示最终排班人员。
2. 未发生业务变更的班次，最终人员即原始排班人员。
3. 换班、请假顶班或历史修正生效后，排班表立即显示最终人员；原始人员不在日常格子中占位。
4. 发生变更的班次显示轻量标记，例如“换”“请”“顶”“修”。
5. 历史班次仍显示最终人员；原始基线和完整链路在值班变更台账中追溯。

### 2.2 月历与班次详情

月历保持“一天一个格子”，不在小格中堆叠编辑、换班、请假等按钮。

日格仅展示摘要：

```text
7 日 [换 1]

早：B
中：C、D
晚：E
```

- 每个班次显示班次简称和最终人员；
- 变更使用小标记提示；
- 点击日格，打开“当日班次详情”右侧抽屉；
- 抽屉按早、中、晚等班次展示多张班次卡片。

班次卡片展示：班次、最终值班人员、业务变更摘要和当前角色可用操作。

有变更时，仅展示受影响关系，例如“已生效换班：A → B”；不并列展示原始与最终两套完整名单。完整原始名单、最终名单和变更链路进入值班变更台账查看。

待处理业务不会改变最终排班展示。例如换班待主任审批时，排班表仍显示 A，同时在班次详情显示“拟变更：A → B，待主任审批”。

### 2.3 操作权限

| 角色 | 点击任意班次格 | 点击本人班次格 |
|---|---|---|
| 值机员 | 查看班次详情 | 发起换班、发起请假、查看或撤回本人申请 |
| 副主任、机房主任、排班管理员 | 编辑最终排班、查看变更摘要 | 在左列基础上增加发起换班、发起请假 |
| 财务/统计 | 查看班次详情 | 无业务发起操作 |
| 系统管理员 | 按当前机房上下文查看；业务操作仍受本人班次和业务状态约束 | 同上 |

### 2.4 换班发起交互

1. 用户从本人具体班次卡片选择“发起换班”。
2. 系统自动带入该班次并打开换班申请弹窗。
3. 选择目标人员后：
   - 互换班次：在目标人员的已发布班次日历中点击目标班次；保留列表选择作为兜底；
   - 单向替班：仅选择目标人员。
4. 目标人员必须是同机房、启用、已绑定启用账号的值机员；本人不可作为目标人员。
5. 未绑定账号的同机房值机员可展示为置灰项，并提示“未绑定启用账号，无法确认换班”；没有可确认对象时禁止提交，并引导到“账号角色”页完成配置。

## 3. 值班变更台账

### 3.1 页面定位

原“实际值班”菜单、页面标题和面包屑统一调整为**值班变更台账**。

值班变更台账不是第二张全量排班表，而是最终排班变化的追溯页面，服务于主任核对、财务/统计复核、导出和审计。

### 3.2 记录粒度与字段

台账只保存发生变更的记录；一条记录描述一次人员变化，而不是每个未变更班次都生成一条台账。

| 字段 | 说明 |
|---|---|
| 日期、班次、班次时间 | 被变更班次 |
| 原始排班人员 | 发布排班时的基线人员 |
| 变更前人员 | 本次变更前的最终人员 |
| 变更后人员 | 本次变更后的最终人员 |
| 变更类型 | 换班、请假顶班、历史人工修正等 |
| 来源业务单 | 关联业务单号或人工修正单号 |
| 审批/修正信息 | 申请、确认、审批或修正人、时间、原因 |

台账支持按日期、班次、人员和变更类型查询；可从排班表变更标记直接进入。

## 4. 历史班次与历史修正

### 4.1 历史状态

统一口径为：

> 今天以前进入历史状态，关闭普通换班、请假、顶班流程；主任、副主任可通过历史修正直接调整最终排班。

| 班次日期 | 可用操作 |
|---|---|
| 今天及以后 | 正常换班、请假、顶班、排班编辑 |
| 今天以前 | 仅机房主任、副主任可执行历史修正 |

“历史状态”不等同于完全不可修改：它限制普通流程，保留有留痕的管理修正能力。

### 4.2 历史修正流程

在历史班次的详情卡片中，仅机房主任、副主任可见“历史修正”。修正表单包含：日期、班次、当前最终人员、修正后人员和必填修正原因。

提交后立即：

1. 更新该班次最终排班；
2. 追加一条“历史人工修正”值班变更台账；
3. 记录原始排班、修正前最终人员、修正后最终人员、修正人、时间和原因；
4. 无需额外审批；
5. 若受影响月份已生成退费、考勤或报表，标记为“数据已变更，需重新计算”，但不阻止修正提交。

## 5. 结算与历史数据

原设计的“月度锁定”与当前代码的整套排班 `locked` 状态均不足以表达日常历史班次处理：

- 原设计的月度锁定属于结算完成后的历史归档；
- 当前整套排班锁定过于粗粒度，不能按日期处理历史班次；
- 后续实现应以班次日期判断历史状态，不再以整套排班状态阻止所有日期操作。

退费、考勤、报表已经生成后，如发生历史修正：

- 不阻止主任、副主任完成修正；
- 标记受影响月份需重新计算；
- 第一阶段可重新计算并更新未正式导出的结果；
- 后续如需保留已导出或已对账结果，可增加“修正版本”机制。
