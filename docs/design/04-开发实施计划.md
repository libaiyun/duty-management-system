# 开发实施计划

## 1. 文档范围

本文基于以下设计文档拆分广播电视台站值班管理系统的实施计划：

- `docs/design/01-需求分析.md`
- `docs/design/02-原型设计.md`
- `docs/design/03-总体设计.md`
- `docs/design/06-设计修订.md`（菜单结构、页面设计、角色权限以本文为准）

拆分粒度为：

```text
Milestone -> Phase -> Task
```

每个 Task 均要求：

- 可独立开发。
- 可独立测试。
- 可独立 Review。
- 可独立提交 Git。
- 有明确依赖关系和完成标准。

首期目标是完成 Web 后台系统，覆盖多台站、多机房、账号权限、基础资料、自动排班、排班调整发布、换班、请假、顶班、审批、实际值班、退费、考勤、Excel 导出、操作日志、备份归档入口。微信小程序首期不开发，仅保留账号微信绑定字段和后续接口扩展空间。

## 2. 总体里程碑

| Milestone | 名称 | 目标 | 主要交付 |
| --- | --- | --- | --- |
| M1 | 工程基础与开发框架 | 建立前后端、数据库、任务、部署和测试基础 | 可运行的空系统、登录骨架、迁移和 CI 基础 |
| M2 | 认证权限与基础资料 | 完成账号、角色、组织、人员、班次规则、节假日标准 | 系统基础数据可维护，可按权限访问 |
| M3 | 排班核心链路 | 完成排班规则模型重构、排班生成、调整、发布、实际值班初始化、值班表导出 | 排班可生成、可调整、可发布、可导出 |
| M4 | 申请审批与实际值班变更 | 完成换班、请假、顶班、审批中心和实际值班同步 | 申请审批闭环，实际值班结果正确 |
| M5 | 退费、考勤与报表 | 完成退费计算、考勤生成、Excel 导出和导出历史 | 月度统计和财务指导表可生成、复核、锁定、导出 |
| M6 | 日志审计、通知与运维 | 完成操作日志、站内通知、备份归档入口、定时任务 | 系统可追溯、可提醒、可维护 |
| M7 | 系统验收与发布准备 | 完成端到端验收、权限验收、性能与部署验收 | 可部署到测试/生产环境的首期版本 |

## 3. 全局依赖关系

```text
M1 工程基础
  -> M2 认证权限与基础资料
    -> M3 排班核心链路
      -> M4 申请审批与实际值班变更
        -> M5 退费、考勤与报表
          -> M6 日志审计、通知与运维
            -> M7 系统验收与发布准备
```

跨模块关键依赖：

- 认证与数据权限是所有业务 API 和页面的前置依赖。
- 组织、人员、班次定义、节假日是排班规则配置和生成的前置依赖。
- 规则发布后才能生成排班；排班存在后才能发起换班、请假和顶班。
- 实际值班记录是退费、考勤和报表计算的唯一口径。
- 月份锁定会限制排班、申请、退费、考勤等写操作。
- 操作日志应逐步接入所有写操作，核心业务完成后必须补齐审计覆盖。

## 11. Task 开发约束

每个 Task 开发时遵守以下约束：

- 一个 Task 对应一个清晰 Git 提交或一个小型 PR。涉及多页面合并的 Task（如排班表、审批中心、退费管理、请假记录），拆分为后端 API + 前端页面两个独立 Task。
- 后端 Task 必须至少包含服务层或 API 层测试；纯迁移 Task 必须包含迁移执行验证。
- 前端 Task 必须完成基础交互和权限/状态禁用逻辑；复杂页面至少有组件测试或可复现手工验收记录。
- 涉及状态流转的 Task 必须测试成功路径、拒绝路径、重复操作和锁定冲突。
- 涉及金额或统计的 Task 必须用固定样例测试计算结果。
- 涉及导出的 Task 必须测试文件生成、表头、关键数据和下载鉴权。
- 涉及写操作的 Task 在 M6 之后必须接入操作日志；M6 之前完成的写操作在 M6-P1-T3 统一补齐。

## 12. 首期完成标准

首期项目完成需同时满足：

- Web 后台可通过用户名密码登录。
- 角色、菜单权限、数据范围生效。
- 可维护多台站、多机房、人员、账号、班次定义、排班规则（N 天循环表格）、节假日。
- 可按规则表驱动生成排班，支持调整、发布、查看和按月导出。
- 值机员在排班表查看全员排班（本人高亮），通过排班表发起换班、请假。
- 机房主任在审批中心审批换班、请假，在请假记录页安排顶班。
- 换班、请假、顶班生效后实际值班记录正确更新。
- 退费按实际值班对象计算，支持餐补退费和法定节假日加班费退费明细与汇总。
- 月度考勤可生成、查看、锁定和导出。
- 导出历史可查询和下载。
- 历史月份锁定后禁止修改相关业务数据。
- 登录、审批、排班调整、导出、退费、考勤、基础资料变更等关键操作有日志。
- Docker Compose 可部署 backend、frontend/nginx、PostgreSQL、Redis、worker、scheduler。
- 端到端验收测试覆盖排班、换班、请假顶班、退费、考勤、权限和锁定。
