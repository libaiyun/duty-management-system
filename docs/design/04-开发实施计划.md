# 开发实施计划

## 1. 文档范围

本文基于以下设计文档拆分广播电视台站值班管理系统的实施计划：

- `docs/design/01-需求分析.md`
- `docs/design/02-原型设计.md`
- `docs/design/03-总体设计.md`
- `docs/design/06-设计修订.md`（菜单结构和页面设计仍适用；与后续修订冲突时以后续修订为准）
- `docs/design/07-值班展示与变更台账设计修订.md`（最终排班、变更台账和历史修正以本文为准）
- `docs/design/08-权限体系设计修订.md`（人员类型、业务资格、账号权限、RBAC、机房边界、个人业务操作和取消月份锁定以本文为准）
- `docs/design/09-费用规则与退费结算设计修订.md`（法定节假日、机房费用规则和退费结算以本文为准）

本轮从 M4-P3 开始重排后续实施和验收计划；M4-P2 及以前任务保留原实施记录，其中与最新修订冲突的最终数据模型和行为，以最终 baseline 与 M7 验收标准收敛到最新设计。

拆分粒度为：

```text
Milestone -> Phase -> Task
```

每个 Task 均要求：

- 可独立开发。
- 可独立测试。
- 可独立 Review。
- 可独立提交 Git。
- 有明确依赖关系和完成标准。

首期目标是完成 Web 后台系统，覆盖多台站、多机房、账号权限、基础资料、自动排班、排班调整发布、换班、请假、顶班、审批、实际值班、退费、考勤、Excel 导出、操作日志、备份归档入口。微信小程序首期不开发，仅保留账号微信绑定字段和后续接口扩展空间。

## 3. 全局依赖关系

```text
M1 工程基础
  -> M2 认证权限与基础资料
    -> M3 排班核心链路
      -> M4 申请审批与实际值班变更
        -> M5 费用规则、退费、考勤与报表
          -> M6 日志审计、通知与运维
            -> M7 系统验收与发布准备
```

跨模块关键依赖：

- 认证与功能权限是管理功能 API 和页面的前置依赖；个人业务操作改按本人身份、人员资格、机房归属和业务状态校验。
- 组织、人员、班次定义及 M2 的节假日基础能力是排班规则配置、生成和请假校验的前置依赖；M5 将该能力重构为系统级法定节假日，并供排班标记、费用规则和退费结算使用。
- 规则发布后才能生成排班；排班存在后才能发起换班、请假和顶班。
- 实际值班记录是退费、考勤和报表计算的唯一口径。
- 普通排班调整、换班、请假和顶班按班次日期限制；历史修正会将已生成的退费标记为需重新结算、考勤标记为需重新生成。
- 操作日志应逐步接入所有写操作，核心业务完成后必须补齐审计覆盖。

## 11. Task 开发约束

每个 Task 开发时遵守以下约束：

- 一个 Task 对应一个清晰 Git 提交或一个小型 PR。涉及多页面合并的 Task（如排班表、审批中心、退费管理、请假记录），拆分为后端 API + 前端页面两个独立 Task。
- 后端 Task 必须至少包含服务层或 API 层测试；纯迁移 Task 必须包含迁移执行验证。
- 前端 Task 必须完成基础交互和权限/状态禁用逻辑；复杂页面至少有组件测试或可复现手工验收记录。
- 涉及状态流转的 Task 必须测试成功路径、拒绝路径、重复操作、历史日期限制和并发冲突。
- 涉及功能权限的 Task 必须同时覆盖角色授权、账号直接授权、无权限和超级管理员放行；不得以人员类型或固定角色编码代替权限校验。
- 个人业务操作必须分别验证“无功能权限仍可操作本人数据”与“非本人、跨机房、资格不符或状态不符时被拒绝”。
- 涉及金额或统计的 Task 必须用固定样例测试计算结果。
- 涉及导出的 Task 必须测试文件生成、表头、关键数据和下载鉴权。
- 涉及写操作的 Task 在 M6 之后必须接入操作日志；M6 之前完成的写操作在 M6-P1-T3 统一补齐。

## 12. 首期完成标准

首期项目完成需同时满足：

- Web 后台可通过用户名密码登录。
- 可管理账号、职责角色和系统权限点；有效权限按“角色权限并集 + 账号直接权限”计算，可查看权限来源。
- 超级管理员不依赖角色或权限记录；内置系统管理员角色的权限可调整，新权限不自动授予。
- 菜单、页面操作和后端 API 权限校验一致；普通账号的机房业务数据固定限于绑定人员所属机房。
- 可维护多台站、多机房、人员、账号、班次定义、排班规则（N 天循环表格）和系统级法定节假日；法定节假日支持年度自动推算、预览和人工修订。
- 可按规则表驱动生成排班，支持调整、发布、查看和按月导出。
- 只有值机员可参与周期排班；非值机员不得设置为参与排班。
- 绑定有效账号的值机员可查看本人排班并发起、撤回本人换班和请假；个人业务不要求功能权限。
- 具备对应权限的账号可审批换班、请假并安排顶班，不以人员类型或固定角色判定。
- 顶班人仅限检修班、机房主任或机房副主任；值机员不得作为请假流程中的顶班人。
- 换班、请假、顶班生效后实际值班记录正确更新。
- 可按机房启用餐补、节假日加班费及其退费规则；未启用退费规则的机房不展示退费结算入口。
- 退费按最终实际值班人员及所选规则集合计算，支持餐补和法定节假日加班费；按付款/收款班次集合分摊，以分计算和固定排序处理尾差，生成收支平衡的明细、人员净额汇总和红包结算表。
- 月度考勤可生成、查看、确认/锁定和导出；批次锁定仅属于报表生命周期。
- 导出历史可查询和下载。
- 普通排班调整、换班、请假和顶班按班次日期限制；历史数据通过必填原因的独立历史修正功能处理并写入变更台账。
- 历史修正影响已生成结果时，退费批次标记为需重新结算、考勤批次标记为需重新生成；系统不提供跨模块月份锁定。
- 登录、审批、排班调整、法定节假日、费用规则、导出、退费结算、考勤、基础资料变更等关键操作有日志。
- Docker Compose 可部署 backend、frontend/nginx、PostgreSQL、Redis、worker、scheduler。
- 端到端验收测试覆盖排班、换班、请假顶班、费用规则、退费结算、考勤、RBAC + 账号直接权限、个人业务例外、机房边界、历史修正和批次失效联动。
