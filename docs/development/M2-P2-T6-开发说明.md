## 数据模型

### shift_rule

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint | PK | 规则 ID |
| org_unit_id | bigint | FK org_unit.id nullable | 适用台站/机房 |
| code | varchar(64) | unique | 规则编码 |
| name | varchar(128) | not null | 规则名称 |
| station_type | varchar(64) | not null | station_broadcast/station_satellite |
| persons_per_shift | int | default 2 | 每班人数 |
| rule_type | varchar(32) | default 'broadcast_fixed' | broadcast_fixed/custom |
| status | varchar(32) | default 'draft' | draft/enabled/disabled |
| remark | text | nullable | 规则说明 |

### shift_rule_item

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint | PK | 明细 ID |
| rule_id | bigint | FK shift_rule.id ON DELETE CASCADE | 所属规则 |
| group_type | varchar(32) | not null | night_early_group/middle_group |
| sequence_no | int | default 0 | 轮班顺序 |
| shift_code | varchar(32) | not null | early/middle/night/rest |
| repeat_count | int | default 1 | 重复次数 |
| remark | varchar(255) | nullable | 说明 |

`shift_rule_item.rule_id` 建立索引 `ix_shift_rule_item_rule_id`。

## API 端点

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/v1/shift-rules` | 查询规则列表（含明细） | `shift:rule:view` |
| POST | `/api/v1/shift-rules` | 新增规则（含编码唯一性、组织存在性校验，可带明细） | `shift:rule:view` |
| GET | `/api/v1/shift-rules/{id}` | 查询规则详情（含明细） | `shift:rule:view` |
| PUT | `/api/v1/shift-rules/{id}` | 编辑规则；`items` 传入则整体替换，省略则保留 | `shift:rule:view` |
| DELETE | `/api/v1/shift-rules/{id}` | 删除规则；被排班引用时拒绝 | `shift:rule:view` |

权限码沿用 T5 已存在的 `shift:rule:view`（`cli.py` 已 seed），本 Task 不新增权限码。

## 业务校验

- **编码唯一性**：`code` 重复创建返回 409 `STATE_CONFLICT`。
- **组织存在性**：`org_unit_id` 指定但不存在时返回 404 `NOT_FOUND`。
- **每班人数**：`persons_per_shift >= 1`，违反由 pydantic 校验返回 400 `VALIDATION_ERROR`。
- **明细更新语义**：`PUT` 请求中 `items` 为 `null`（省略）时保留原明细；传入数组（含空数组）时整体替换，通过 `cascade="all, delete-orphan"` 清理旧明细。明细统一按 `sequence_no` 升序持久化，保证创建/编辑响应与后续查询顺序一致。
- **被引用不可删除**：若 `monthly_schedule` 表已存在（M3 之后）且引用了该规则，删除返回 409 `STATE_CONFLICT`；当前阶段该表不存在，探测直接返回未被引用。

```bash

docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend ruff check backend/app
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend mypy
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend pytest
# 迁移双向验证
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend alembic upgrade head
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend alembic downgrade -1
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm --no-deps backend alembic upgrade head
```

结果：ruff 通过；mypy 46 文件无问题；pytest 139 passed；迁移 upgrade/downgrade/upgrade 均成功。

> 注意：`alembic` 命令必须带 `docker-compose.dev.yml` 覆盖运行，因为只有 dev 覆盖挂载了 `./backend/alembic` 目录；基础 compose 使用镜像内构建产物，不会包含新增迁移文件。
