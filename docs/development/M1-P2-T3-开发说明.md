# M1-P2-T3 开发说明

## Task 范围

本次仅完成 `M1-P2-T3 API 请求封装与错误处理`。

实施范围：

- 扩展 `src/types/api.ts`：新增 `PageParams`、`PageResponse<T>`、`ApiErrorDetail`、`ErrorResponse` 类型。
- 重写 `src/services/http.ts`：
  - 新增 `post()`、`put()`、`delete()` 方法。
  - 新增 `getPage()` 分页请求方法，传入 `PageParams` 自动构建查询参数。
  - 新增 Token 注入：通过 `getToken` 回调自动附加 `Authorization: Bearer <token>`。
  - 新增 `onUnauthorized` 回调：401 响应时调用，供页面层跳转登录。
  - 新增错误处理：
    - HTTP 状态非 2xx 时抛出 `ApiError`。
    - 响应体 `code !== 'OK'` 时抛出 `ApiError`。
    - 网络连接失败时抛出 `NetworkError`。
    - 非 JSON 错误响应体容错处理。
  - `ApiError` 包含 `status`、`code`、`message`、`traceId`、`details`。
- 新增 `src/services/http.ts` 导出：`ApiError`、`NetworkError`、`parseApiError`、`HttpClient`、`httpClient`。
- 补充单元测试覆盖全部 HTTP 方法、Token 注入、分页、错误处理和容错场景。

未实施范围：

- Pinia store 集成自动提供 token，属于后续 Task 结合认证模块实现。
- 请求重试、请求取消、超时配置，属于后续优化。
- 请求拦截器和响应拦截器链式回调，首期保持简单直接式。
- 前端全局错误消息提示 UI 组件，属于后续 Task。

## API 客户端 API

### 实例化

```typescript
import { HttpClient } from '@/services/http'

const client = new HttpClient({
  baseUrl: '/api/v1',
  callbacks: {
    getToken: () => store.token,
    onUnauthorized: () => router.push('/login'),
  },
})
```

默认导出 `httpClient` 单例：

```typescript
import { httpClient } from '@/services/http'
```

### 请求方法

| 方法 | 签名 | 说明 |
|------|------|------|
| `get<T>` | `(path: string) => Promise<ApiResponse<T>>` | GET 请求 |
| `post<T>` | `(path: string, body?: unknown) => Promise<ApiResponse<T>>` | POST 请求，自动序列化 JSON body |
| `put<T>` | `(path: string, body?: unknown) => Promise<ApiResponse<T>>` | PUT 请求 |
| `delete<T>` | `(path: string) => Promise<ApiResponse<T>>` | DELETE 请求 |
| `getPage<T>` | `(path: string, params: PageParams) => Promise<ApiResponse<PageResponse<T>>>` | 分页 GET 请求 |

### 使用示例

```typescript
// 普通请求
const res = await httpClient.get<{ status: string }>('health')

// POST 请求
const res = await httpClient.post<{ id: number }>('/items', { name: 'test' })

// 分页请求
const res = await httpClient.getPage<Person>('/persons', { page: 1, page_size: 20 })
console.log(res.data.items, res.data.total, res.data.total_pages)
```

### 错误处理

```typescript
import { ApiError, NetworkError } from '@/services/http'

try {
  const res = await httpClient.get('data')
} catch (err) {
  if (err instanceof ApiError) {
    console.log(err.code, err.message, err.traceId, err.details)
  } else if (err instanceof NetworkError) {
    console.log('网络不可用:', err.message)
  }
}
```

## 错误类型

| 类型 | 触发条件 | 属性 |
|------|----------|------|
| `ApiError` | HTTP 非 2xx 或 `code !== 'OK'` | `status`、`code`、`message`、`traceId`、`details` |
| `NetworkError` | `fetch` 本身抛出异常 | `message` |

## 当前测试覆盖

- GET 请求和 JSON 解析。
- POST 请求和 JSON body 序列化。
- PUT 请求和 body 传递。
- DELETE 请求。
- `getToken` 回调注入 `Authorization` header。
- `getToken` 返回 null 时不注入 header。
- `getPage` 请求构建正确的 query 参数。
- 非 2xx HTTP 状态抛出 `ApiError`，包含 `status`、`code`、`message`、`traceId`。
- 业务错误（`code !== 'OK'`）抛出 `ApiError`。
- 校验错误（400）携带 `details` 字段。
- 401 响应触发 `onUnauthorized` 回调。
- 非 JSON 错误响应体容错处理。
- 网络连接失败抛出 `NetworkError`。
- 非 Error 类型的 connect 异常使用中文兜底消息。

## 说明

- 当前 `httpClient` 导出的默认实例未配置 `getToken` 和 `onUnauthorized` 回调，将在 `M2-P1` 认证模块中与 Pinia store 和 Router 集成。
- `getPage` 方法将 `page` 和 `page_size` 拼接为 URL query string，暂不支持额外自定义查询参数——需要时可在 `path` 中预置 `?key=value`。
- `Content-Type: application/json` 仅在传入 `body` 时设置，GET/DELETE 请求不带 Content-Type。
