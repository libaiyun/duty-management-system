# M3-P1-T5 重构开发说明

## 背景

原 `M3-P1-T5-开发说明.md` 对应旧版"排班日历页"：页面按机房查询排班摘要，再跳转至排班明细页。该实现与 `docs/design/06-设计修订.md` 不一致，现由本次重构替代。

本次以 `04-开发实施计划.md` 修订后的 M3-P1-T5 为准，实施"排班表前端页面（日历+列表视图）"，并补齐其依赖的用户机房上下文和排班详情数据范围校验。

## 实施范围

### 用户与机房上下文

- `GET /api/v1/auth/me` 增加 `person_id`、`room_id`、`room_name`、`can_switch_room`。
- 普通用户从绑定人员获取所属机房；全局数据范围用户标记为可切换机房。
- 前端 `auth` store 保存人员和机房信息。
- 新增 `room-context` store：普通用户使用所属机房；系统管理员可保存当前选择机房。
- HTTP 请求在存在当前机房时携带 `X-Current-Room-Id` 请求头，为后续机房相关接口复用预留。
- 顶部栏普通用户显示"姓名 · 机房名"；可切换机房用户显示机房下拉框；全局页面隐藏下拉框。

### 排班接口范围校验

- 排班表按当前机房返回全员排班；值机员仍仅能发起本人相关的换班、请假操作。
- `/schedules/{id}`、`/schedules/{id}/days`、`/schedules/{id}/days/range`、`/schedules/{id}/generate` 均校验排班所属机房在当前用户数据范围内。
- 越权访问其他机房排班按资源不存在返回 404。

### 排班表页面

- 删除旧 `ScheduleCalendarView.vue` 和旧 `monthly-schedule` 路由入口。
- 新增 `ScheduleTableView.vue` 和 `schedule-table` 路由（`/schedule-mgmt/table`）。
- 页面按当前机房查询唯一排班主记录，并通过 `/schedules/{id}/days?year=&month=` 加载月度日班次。
- 默认日历视图：按班次展示人员、本人日期高亮、法定节假日标识、锁定状态展示。
- 列表视图：日期为行、班次为动态列，支持日期范围、班次、人员筛选。
- 点击本人班次日期展示换班/请假占位操作；法定节假日请假禁用。换班、请假实际业务将在 M4 实现。
- 本次不实现排班编辑；主任/管理员编辑人员弹窗留待 M3-P2-T4。
- 导出按钮保留为占位，值班表导出在 M3-P3 实现。

## 测试覆盖

### 后端

- `/auth/me` 返回绑定人员与所属机房。
- 无全局范围用户不能读取其他机房的排班详情和日班次。
- 全量业务测试覆盖排班表全员展示和跨机房范围校验。

### 前端

- 排班表标题和无机房筛选器。
- 当前机房排班和月度日班次请求。
- 日历班次人员展示。
- 本人日期和法定节假日标记。
- 列表视图与动态班次列。
- `schedule-table` 路由和权限。

- 当前机房请求头已由前端发送；后续机房相关接口应统一读取并验证该上下文。当前排班接口已经通过用户数据范围校验防止越权。
