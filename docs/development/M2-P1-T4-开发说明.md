## 核心实现

### `RequirePermission` 依赖类 (`app/api/deps.py`)

```python
class RequirePermission:
    def __init__(self, permission_code: str) -> None:
        self.permission_code = permission_code

    def __call__(
        self,
        request: Request,
        db: Session = Depends(get_db),
        settings: Settings = Depends(_get_settings),
    ) -> SysUser:
        user = get_current_user(settings, request, db)
        if not check_user_permission(db, user, self.permission_code):
            raise ForbiddenError(message=f"缺少权限: {self.permission_code}")
        return user
```

使用方式（在路由中声明）：

```python
# 处理函数不需要 user 对象
@router.post("/password/reset", ...)
def reset_password(
    ...
    _user: None = Depends(RequirePermission("system:user:manage")),
) -> ...:
    ...

# 处理函数需要 user 对象
@router.post("/some-action", ...)
def some_action(
    ...
    current_user: SysUser = Depends(RequirePermission("schedule:monthly:generate")),
) -> ...:
    ...
```

请求处理流程：

1. FastAPI 解析 `Authorization: Bearer <token>` → `get_current_user` → 校验登录态 + 账号状态
2. `check_user_permission` 查询 `sys_permission` JOIN `sys_role_permission` JOIN `sys_user_role`，验证权限码存在
3. 不持有权限 → `ForbiddenError` (403)
4. 持有权限 → 继续执行路由处理函数

### `check_user_permission` 服务函数 (`app/services/auth.py`)

```python
def check_user_permission(db: Session, user: SysUser, permission_code: str) -> bool:
    stmt = (
        exists()
        .where(
            SysPermission.code == permission_code,
            SysPermission.id == sys_role_permission.c.permission_id,
            sys_role_permission.c.role_id == sys_user_role.c.role_id,
            sys_user_role.c.user_id == user.id,
        )
    )
    return db.scalar(select(stmt)) or False
```

通过 M2M 关联表直接 JOIN 查询，避免 ORM 懒加载导致的 N+1 问题。

### `_get_settings` 统一提取 (`app/api/deps.py`)

原先定义在 `routes/auth.py` 中，现移到 `app/api/deps.py` 供所有路由模块共用。

```python
def _get_settings(request: Request) -> Settings:
    return request.app.state.settings
```

## API 权限对照

|------|---------|------|
| `POST /auth/login` | 无 | 所有人可访问 |
| `POST /auth/refresh` | 无 | 仅需 refresh token |

## 说明

- `check_user_permission` 通过 M2M 关联表直接查询，不依赖 ORM 关系懒加载，支持任意用户和任意权限码组合的精确检查。
- `RequirePermission` 同时完成认证（401）和授权（403）两层校验：未登录返回 401，无权限返回 403。
- 权限码格式遵循总体设计 10.3 节的 `模块:资源:动作` 规范，例如 `system:user:manage`、`schedule:monthly:view`。
- 测试辅助函数 `_grant_permission` 通过创建角色 + 权限 + 关联实现完整链路，确保与生产环境的权限数据结构一致。
- `reset_password` 是首个接入权限控制的端点，后续所有写操作端点按业务需求声明各自权限码。
- 预留了 `RequirePermission` 返回 `None` 的模式（`_perm: None = Depends(RequirePermission(...))`），若路由处理函数需要用户对象，可改为 `_user: SysUser = Depends(...)` 返回用户实例。
