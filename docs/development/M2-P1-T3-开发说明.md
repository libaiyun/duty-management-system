# M2-P1-T3 开发说明

## Task 范围

本次仅完成 `M2-P1-T3 密码哈希与账号状态校验`。

实施范围：

- 新增 `change_own_password` 服务函数：用户自行修改密码，需验证原密码正确。
- 新增 `reset_user_password` 服务函数：管理员重置任意用户密码，无需原密码。
- 新增 `ChangePasswordRequest` / `ResetPasswordRequest` Pydantic schema。
- 新增 `PUT /api/v1/auth/password` 接口：用户修改自己的密码。
- 新增 `POST /api/v1/auth/password/reset` 接口：管理员重置用户密码（需登录态，T4 补权限校验）。
- 新增 11 个单元测试覆盖所有成功和失败路径。

未实施范围：

- 密码强度策略（长度、复杂度、历史密码校验），属于后续安全加固。
- 管理员重置密码的权限校验（仅系统管理员/特定角色可执行），属于 `M2-P1-T4`。
- Token 黑名单和强制所有会话下线（密码修改后不影响已签发 token），属于 `M6`。
- 密码有效期、密码过期提醒，属于后续扩展。

## API 详情

### PUT /api/v1/auth/password — 修改自身密码

```json
// Request
{
  "old_password": "currentpass",
  "new_password": "newpass456"
}

// Response 200
{ "code": "OK", "message": "密码修改成功" }

// Response 401 — 未登录
{ "code": "UNAUTHORIZED", "message": "未登录或登录已过期" }

// Response 422 — 原密码错误
{ "code": "BUSINESS_RULE_FAILED", "message": "原密码错误" }

// Response 422 — 新旧密码相同
{ "code": "BUSINESS_RULE_FAILED", "message": "新密码不能与原密码相同" }
```

### POST /api/v1/auth/password/reset — 管理员重置用户密码

```json
// Request
{
  "user_id": 42,
  "new_password": "resetpass789"
}

// Response 200
{ "code": "OK", "message": "密码重置成功" }

// Response 401 — 未登录
{ "code": "UNAUTHORIZED", "message": "未登录或登录已过期" }

// Response 404 — 用户不存在
{ "code": "NOT_FOUND", "message": "用户不存在或已注销" }
```

## 服务层函数

### `change_own_password(db, user, old_password, new_password)`

| 参数 | 类型 | 说明 |
|------|------|------|
| `db` | `Session` | 数据库会话 |
| `user` | `SysUser` | 当前登录用户 |
| `old_password` | `str` | 原密码（明文） |
| `new_password` | `str` | 新密码（明文） |

校验：
- 原密码必须与 `user.password_hash` 匹配，否则抛出 `BusinessRuleError`。
- 新密码不能与原密码相同。

成功后更新 `user.password_hash` 为 bcrypt 哈希值，调用 `db.flush()`，不返回用户对象。

### `reset_user_password(db, user_id, new_password)`

| 参数 | 类型 | 说明 |
|------|------|------|
| `db` | `Session` | 数据库会话 |
| `user_id` | `int` | 目标用户 ID |
| `new_password` | `str` | 新密码（明文） |

校验：
- 目标用户必须存在，否则抛出 `NotFoundError`。
- 不校验目标用户的 status（disabled/locked 用户也允许重置，后续管理员可重新启用）。

成功后更新 `user.password_hash` 为 bcrypt 哈希值，调用 `db.flush()`。

## 说明

- 密码哈希和验证复用 `M2-P1-T2` 中已有的 `hash_password` / `verify_password`（bcrypt）。
- 账号状态（enabled/disabled/locked）校验已在 `M2-P1-T2` 的 `authenticate_user` 和 `get_current_user` 中实现，T3 不做重复校验。
- `reset_password` 接口当前仅要求登录态，权限校验（仅系统管理员可调用）将在 `M2-P1-T4` 中通过权限中间件补充。
- 密码修改后，已签发的旧 token 仍然有效，Token 黑名单和强制下线机制属于 `M6` 范围。
- 密码长度由 `ChangePasswordRequest` / `ResetPasswordRequest` 的 Pydantic `Field(min_length=1, max_length=128)` 控制，不引入额外密码策略。
