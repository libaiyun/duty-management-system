# M1-P3-T1 开发说明

## Task 范围

本次仅完成 `M1-P3-T1 Docker Compose 开发环境`。

实施范围：

- 新增 `Dockerfile`：基于 `python:3.13-slim`，安装 gcc 和 libpq-dev，使用 `pip install -e ".[test]"` 安装依赖。
- 新增 `.dockerignore`：排除 `.git`、`.venv`、`node_modules`、`frontend/dist`、`data/` 等不需要构建的文件。
- 新增 `docker-compose.yml`（基础编排）：
  - `backend` 服务：构建自 `Dockerfile`，依赖 `db` 和 `redis` 的健康检查，暴露 8000 端口。
  - `db` 服务：`postgres:16`，自动创建 `duty_system` 数据库和 `duty_app` 用户。
  - `redis` 服务：`redis:7`，开启 AOF 持久化。
  - 网络隔离 `duty_net`，独立持久化卷 `postgres_data` 和 `redis_data`。
- 新增 `docker-compose.dev.yml`（开发覆盖）：
  - 挂载 `backend/app`、`backend/tests`、`backend/alembic` 为只读卷。
  - 覆盖启动命令为 `uvicorn --reload` 启用热重载。
- 新增 `deploy/env/dev.env`：开发环境变量，数据库和 Redis 地址指向容器内服务名（`db`、`redis`）。
- 更新 `pyproject.toml`：
  - 新增 `[build-system]` 配置（setuptools）。
  - 新增 `[tool.setuptools.packages.find].where = ["backend"]` 避免 flat-layout 包发现冲突。

未实施范围：

- Nginx 反向代理前端静态资源和 `/api`，属于 `M1-P3-T2`。
- Celery Worker 和 Beat 容器，属于 `M6-P3-T1`。
- 生产环境 Compose 配置，属于 `M6-P3-T5`。
- CI 脚本和代码质量工具，属于 `M1-P3-T3`、`M1-P3-T4`。
- 前端 dev server 集成到 Compose，属于 `M1-P3-T2`。

## 服务拓扑

```text
Docker Compose (duty_net)
  ├── backend:8000 (FastAPI + uvicorn)
  │   depends_on: db (healthy), redis (healthy)
  ├── db:5432 (PostgreSQL 16)
  │   user: duty_app, db: duty_system
  └── redis:6379 (Redis 7, AOF 持久化)
```

## 环境变量

开发环境变量文件：`deploy/env/dev.env`

| 变量 | 值 | 说明 |
|------|-----|------|
| `DUTY_APP_ENV` | `dev` | 运行环境 |
| `DUTY_DATABASE_URL` | `postgresql+psycopg://duty_app:duty_app@db:5432/duty_system` | 指向 db 容器 |
| `DUTY_REDIS_URL` | `redis://redis:6379/0` | 指向 redis 容器 |
| `DUTY_JWT_SECRET_KEY` | `dev-only-change-me` | 开发占位密钥 |
| `DUTY_JWT_ALGORITHM` | `HS256` | 签名算法 |

文件存储目录使用代码默认值，未显式设置（开发环境不强制）。

## 运行方式

启动全部服务：

```bash
docker compose up -d
```

使用开发覆盖（热重载、代码挂载）：

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

执行数据库迁移：

```bash
docker compose exec backend alembic upgrade head
```

运行后端测试：

```bash
docker compose exec backend pytest
```

健康检查：

```bash
curl http://localhost:8000/api/v1/health
```

停止并清理：

```bash
docker compose down -v
```

## 说明

- 开发环境 `db` 和 `redis` 不暴露宿主机端口，仅通过 Docker 内部网络 `duty_net` 访问。后端通过服务名 `db` 和 `redis` 连接。
- 生产环境应使用 `deploy/env/prod.env`，强制设置 `DUTY_JWT_SECRET_KEY` 和安全配置。
- `Dockerfile` 基于 `python:3.13-slim`，安装 `gcc` 和 `libpq-dev` 以编译 `psycopg[binary]`。
- `pyproject.toml` 中新增的 `[tool.setuptools.packages.find]` 配置确保在 flat-layout 项目中只搜索 `backend/` 目录下的包。
