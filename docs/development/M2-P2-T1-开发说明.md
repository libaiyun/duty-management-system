# M2-P2-T1 开发说明

## Task 范围

本次仅完成 `M2-P2-T1 组织机构模型与 API`。

实施范围：

- 新增 `models/organization.py` — `OrgUnit` 模型，支持自引用树结构（parent_id FK → 自身）。
- 新增 Alembic 迁移 `m2_p2_t1_org_unit` — 创建 `org_unit` 表。
- 新增 `schemas/org_unit.py` — 请求/响应/TreeNode schema。
- 新增 `api/v1/routes/org_units.py` — 6 个 REST 端点。
- 扩展 `services/auth.py` — 新增 `list_org_units`、`create_org_unit`、`update_org_unit`、`get_org_unit_children`、`check_org_unit_referenced`。
- 新增 11 个单元测试（7 API + 3 模型 + 1 权限）。

未实施范围：

- `manager_person_id` FK 约束（`person` 表属于 `M2-P2-T3`），当前字段预留。
- `sys_data_scope.org_unit_id` FK 约束（后续 Task 补充）。
- 前端台站机房页面，属于 `M2-P2-T2`。

## 数据模型

### org_unit

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint | PK | 组织 ID |
| parent_id | bigint | FK org_unit.id, SET NULL | 上级组织，支持树结构 |
| code | varchar(64) | unique | 组织编码 |
| name | varchar(128) | not null | 名称 |
| type | varchar(32) | not null | station/room/team/department |
| manager_person_id | bigint | nullable | 负责人（M2-P2-T3 建立 FK） |
| status | varchar(32) | not null, default=enable | enabled/disabled |
| sort_order | int | default=0 | 排序 |

自引用关系：`parent_id → org_unit.id`，`children` 按 `sort_order` 排序。

## API 端点

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/v1/org-units` | `org:unit:view` | 组织列表（扁平） |
| GET | `/api/v1/org-units/tree` | `org:unit:view` | 组织树（递归嵌套） |
| POST | `/api/v1/org-units` | `org:unit:view` | 创建组织 |
| GET | `/api/v1/org-units/{id}` | `org:unit:view` | 组织详情 |
| PUT | `/api/v1/org-units/{id}` | `org:unit:view` | 编辑组织 |
| DELETE | `/api/v1/org-units/{id}` | `org:unit:view` | 删除组织（有子组织时 409） |

## 说明

- 组织树通过 `GET /org-units/tree` 递归构建，由路由处理函数中的 `_build_tree()` 完成，不依赖数据库递归 CTE。
- 删除校验仅检查是否有直接子节点（`parent_id` 引用），不检查间接引用。后续 `person` 表（`M2-P2-T3`）和排班表（`M3`）引入后需补充引用检查。
- `manager_person_id` 当前为普通 bigint 字段，FK 约束将在 `M2-P2-T3` 的 person 表迁移中补充。
- 创建/编辑端点复用 `org:unit:view` 权限，后续可在权限码体系中补充独立的 `org:unit:manage` 权限。
