# M2-P1-T1 开发说明

## Task 范围

本次仅完成 `M2-P1-T1 用户、角色、权限数据库模型`。

实施范围：

- 新增 `backend/app/models/base.py`：`BaseModel` 抽象基类，包含公共字段（id、created_at、created_by、updated_at、updated_by、deleted_at、version）。
  - `id` 使用 `BigInteger().with_variant(Integer(), "sqlite")` 兼容 PostgreSQL 和 SQLite 测试环境。
- 新增 `backend/app/models/user.py`：6 个认证权限相关模型和 2 个关联表。
  - `sys_user`：用户表（username、password_hash、display_name、wx_openid、status、last_login_at、person_id）。
  - `sys_role`：角色表（code、name、status、remark）。
  - `sys_permission`：权限表（code、name、type、parent_id、path、action、status）。
  - `sys_user_role`：用户-角色关联表（Composite PK + CASCADE 外键）。
  - `sys_role_permission`：角色-权限关联表（Composite PK + CASCADE 外键）。
  - `sys_data_scope`：数据范围表（role_id、user_id、scope_type、org_unit_id）。
- 更新 `backend/app/models/__init__.py`：导出所有模型，供 Alembic 自动发现。
- 更新 `backend/alembic/env.py`：导入 `app.models` 确保 autogenerate 可发现模型。
- 新增 Alembic 迁移 `m2_p1_t1_auth_tables`：6 张表创建/删除，支持回滚。
- 新增 `backend/tests/test_models_user.py`：14 个模型单元测试覆盖 CRUD、唯一约束、级联删除、关联表、数据范围。

未实施范围：

- 密码哈希和账号状态校验服务，属于 `M2-P1-T3`。
- 登录 Token 签发 API，属于 `M2-P1-T2`。
- 权限校验中间件，属于 `M2-P1-T4`。
- 数据范围过滤服务，属于 `M2-P1-T5`。
- `sys_user.person_id` 外键（person 表属于 `M2-P2`）。
- `sys_data_scope.org_unit_id` 外键（org_unit 表属于 `M2-P2`）。

## 表结构

### sys_user

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 用户 ID（自动递增） |
| person_id | bigint nullable unique | 绑定人员 ID（M2-P2 建立 FK） |
| username | varchar(64) unique not null | 登录名 |
| password_hash | varchar(255) not null | 密码哈希 |
| display_name | varchar(64) not null | 显示名称 |
| wx_openid | varchar(128) nullable unique | 微信 OpenID |
| status | varchar(32) not null | enabled/disabled/locked |
| last_login_at | timestamptz nullable | 最近登录时间 |

### sys_role

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 角色 ID |
| code | varchar(64) unique not null | 角色编码 |
| name | varchar(128) not null | 角色名称 |
| status | varchar(32) not null | enabled/disabled |
| remark | varchar(500) nullable | 备注 |

### sys_permission

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 权限 ID |
| code | varchar(64) unique not null | 权限编码 |
| name | varchar(128) not null | 权限名称 |
| type | varchar(32) not null | menu/button/api |
| parent_id | bigint nullable | 父权限 ID |
| path | varchar(255) nullable | 前端路由路径 |
| action | varchar(64) nullable | 操作动作 |
| status | varchar(32) not null | enabled/disabled |

### sys_data_scope

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 数据范围 ID |
| role_id | bigint nullable FK → sys_role | 关联角色 |
| user_id | bigint nullable FK → sys_user | 关联用户 |
| scope_type | varchar(32) not null | self/room/station/all |
| org_unit_id | bigint nullable | 组织 ID（M2-P2 建立 FK） |

## 运行方式

启动服务并执行迁移：

```bash
docker compose up -d
docker compose exec backend alembic upgrade head
```

测试：

```bash
docker compose exec backend pytest
```

## 当前测试覆盖

- 创建用户，验证默认值（status=enabled, version=1）。
- 用户名唯一约束（重复插入抛出异常）。
- 创建角色和权限，验证默认值。
- 角色编码唯一约束。
- 用户-角色关联（多对多），验证关联表记录。
- 角色-权限关联（多对多），验证关联表记录。
- 删除用户时级联删除关联记录。
- 删除角色时级联删除关联记录。
- 数据范围关联角色/用户。
- 软删除标记（deleted_at）。
- 权限层级关系（parent_id）。
- 模型不污染应用 `Base.metadata`（独立 metadata 管理）。

## 说明

- `id` 字段使用 `BigInteger().with_variant(Integer(), "sqlite")`，在 PostgreSQL 中为 BIGSERIAL（bigint 自增），在 SQLite 中为 INTEGER 自增，兼容两种数据库。
- `person_id` 和 `org_unit_id` 当前为无 FK 的 bigint 字段，在 `M2-P2` 中添加 person 和 org_unit 表后补建 FK 约束。
- 关联表 `sys_user_role` 和 `sys_role_permission` 使用 Composite PK + CASCADE 外键，删除用户/角色时自动清理关联记录。
