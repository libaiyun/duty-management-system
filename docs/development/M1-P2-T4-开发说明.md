## 权限模型

```text
用户 -> 角色 -> 权限码集合
```

首期实现简化模型：权限 store 维护当前用户的权限码 `Set<PermissionCode>`。开发环境默认包含所有权限码。

后续 `M2-P1` 将：
- 从登录接口获取用户权限码列表。
- 根据前端 router `meta.permission` 和用户权限码做路由守卫。
- 根据权限码过滤侧边栏菜单。

## 路由守卫

```typescript
router.beforeEach((to, _from, next) => {
  const permission = to.meta.permission
  if (permission && !permissionStore.hasPermission(permission)) {
    next({ name: 'forbidden' })
    return
  }
  next()
})
```

- 无 `permission` 字段的路由（工作台、403）对所有用户开放。
- 有 `permission` 字段的路由校验用户是否持有对应权限码。
- 校验失败重定向到 `/403`。

## 菜单过滤

`filterMenuByPermission(menus, hasPermission)` 递归过滤菜单树：

- 无 `permission` 的菜单项始终显示（如工作台）。
- 有 `permission` 的菜单项仅当用户持有权限时才显示。
- 父级分组仅当其至少有一个子项可见时才显示。

## 当前测试覆盖

- 权限 store 默认拥有所有权限。
- 权限 store 可设置和清除权限。
- `filterMenuByPermission` 全部权限时返回完整菜单。
- `filterMenuByPermission` 无权限时仅返回工作台。
- `filterMenuByPermission` 部分权限时仅返回匹配的子项和分组。
- 路由叶子节点均分配了 `meta.permission`。
- `/403` 路由已注册。
- `ForbiddenView` 渲染 403 文案和返回按钮。
- 原有 http、store、breadcrumb、router、menu、app-shell 测试继续通过。

## 说明

- 开发阶段默认拥有全部权限，`M2-P1` 登录成功后通过 `permissionStore.setPermissions(codes)` 替换。
- 父级路由（如 `/my-duty`）不分配权限码，其可见性由子项权限决定。
- `PermissionCode` 是联合类型，编译期可校验权限码拼写错误。
- `UserFilled` icon 未使用，但不影响功能。
