## Task 范围

本次完成 `M3-P0 排班规则模型重构`（T1~T3），将 M2-P2-T6 的旧排班规则模型（`group_type`/`sequence_no`/`shift_code`/`repeat_count`）重构为网格规则模型，依据 `docs/design/05-排班规则设计.md`。

- M3-P0-T2：重构 Schema/Service/API，新增发布、版本查询端点；person API 增加过滤参数
- M3-P0-T2：后端验证闭环 —— `start_date` >= 明天、每格人数达标、人员属本机房、循环天数完整；发布时自动生成 365 天排班
- M3-P0-T3：重构前端排班规则页面为 N×M 网格下拉选人
- 测试：新增 27 个测试（18 API + 模型 + 9 验证/生成/过滤）

- 排班明细编辑/发布/锁定端点，属于 `M3-P2`。

## 业务校验

### 创建/编辑规则

- **起始日期**：必须 >= 明天；过去日期返回 422，提示“起始日期必须从明天起”
- **格子完整性**：
  - 每天每格人数必须等于 `persons_per_cell`；不足返回“需要 N 人，当前 M 人”
  - 所有 `day_no` 从 1 到 `cycle_days` 必须补齐；缺失返回“缺少第 X 天的排班数据”
  - 人员必须属于当前机房（`org_unit_id` 非空时校验）
- **编码唯一性**：重复返回 409 `STATE_CONFLICT`
- **组织存在性**：`org_unit_id` 不存在返回 404 `NOT_FOUND`

### 发布规则

- 版本必须存在且处于 `draft` 状态
- 已发布版本不可重复发布，需先修改再发布（`PUT` 后 `days` 生成新 draft 版本）
- 发布成功后将最新版本状态改为 `published`，规则状态改为 `published`
- 若规则关联了 `org_unit_id`，自动从起始日期起生成 365 天排班到 `schedule_day`/`schedule_shift`/`schedule_shift_person`
- 重新发布时，今天之前的日期保留不动，今天起覆盖刷新
