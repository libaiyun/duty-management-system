# M1-P1-T4 开发说明

## Task 范围

本次仅完成 `M1-P1-T4 统一响应、分页和异常处理`。

实施范围：

- 新增统一成功响应模型 `ApiResponse[T]`。
- 新增统一错误响应模型 `ErrorResponse`。
- 健康检查接口改为统一成功响应结构。
- 新增分页参数模型 `PageParams`。
- 新增分页响应模型 `PageResponse[T]`。
- 新增分页依赖 `get_page_params()`。
- 新增应用异常基类 `AppException` 和基础异常类型。
- 注册全局异常处理器，统一处理：
  - 400 参数错误
  - 401 未登录
  - 403 无权限
  - 404 不存在
  - 409 状态冲突
  - 422 业务校验
  - 500 未预期异常

未实施范围：

- 认证和权限判断，属于 `M2-P1`。
- 业务错误码全集，随业务 Task 增量补充。
- 业务分页查询接口，属于后续业务模块。
- 前端 API client 错误处理，属于 `M1-P2-T3`。

## 响应格式

成功响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "trace_id": "trace-id"
}
```

错误响应：

```json
{
  "code": "NOT_FOUND",
  "message": "资源不存在",
  "trace_id": "trace-id"
}
```

参数校验错误会包含 `details`：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "参数校验失败",
  "details": [
    {
      "field": "query.page",
      "message": "Input should be greater than or equal to 1"
    }
  ],
  "trace_id": "trace-id"
}
```

## 分页约定

请求参数：

- `page`：页码，从 1 开始。
- `page_size`：每页数量，范围 1-200，默认 20。

分页响应：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "total_pages": 0
}
```

## 测试方式

```bash
pytest
```

当前测试覆盖：

- 健康检查统一成功响应。
- 成功响应携带 `trace_id`。
- `AppException` 对 400/401/403/404/409/422 的统一错误格式。
- FastAPI `HTTPException` 的统一错误格式。
- FastAPI `HTTPException` 的响应头透传。
- 非标准 HTTP 状态码不会破坏异常处理器。
- 请求参数校验错误的 400 统一错误格式和 `details`。
- 未预期异常的 500 错误格式。
- 分页参数解析、分页响应和非法分页参数。
