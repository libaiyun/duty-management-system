# M2-P1-T6 开发说明

## Task 范围

本次仅完成 `M2-P1-T6 前端登录页与登录状态`。

实施范围：

- 新增 `types/auth.ts` — `LoginRequest` / `TokenResponse` / `UserMeResponse` 类型定义。
- 新增 `stores/auth.ts` — Pinia auth store，管理 login/logout/token 持久化/会话恢复。
- 新增 `views/LoginView.vue` — 登录页面（表单校验、错误提示、登录跳转）。
- 修改 `services/http.ts` — `HttpClient` 新增 `configureCallbacks()` 方法，支持运行时注入 token 和 401 回调。
- 修改 `router/index.ts` — 新增 `/login` 公开路由，`beforeEach` 守卫检测登录态并重定向。
- 修改 `layouts/AppShell.vue` — "退出登录" 按钮接线，调用 `authStore.logout()` 后跳转登录页。
- 修改 `main.ts` — 配置 `httpClient` 的 `getToken` / `onUnauthorized` 回调，启动时恢复会话。
- 新增 3 个测试文件共 20 个单元测试。

未实施范围：

- "记住登录" / 自动刷新 token，属于后续优化。
- 微信扫码登录绑定，属于后续扩展 E1。
- 登录成功后的权限列表从后端同步（当前使用前端默认全权限），属于后续 `M2-P1-T7` 或 `M2-P2`。
- 登录页的验证码、密码强度提示等安全增强。

## 核心实现

### 登录流程

```
LoginView.vue
  → authStore.login(username, password)
    → POST /api/v1/auth/login  → 获取 access_token + refresh_token
    → GET  /api/v1/auth/me     → 获取用户信息
    → 存储 token 到 localStorage + Pinia state
    → 更新 appStore.userName
    → router.replace(redirect)
```

### 退出流程

```
AppShell.vue "退出登录"
  → authStore.logout()
    → POST /api/v1/auth/logout  (尽力调用，失败不影响本地清理)
    → 清除 localStorage 中的 token
    → 清除 appStore.userName
    → 清除 permissionStore.permissions
    → router.push({ name: 'login' })
```

### 路由守卫

```
router.beforeEach
  ├─ 公开路由 (/login, /403, /404) → 放行
  ├─ 未登录 → 重定向 /login?redirect=原始路径
  ├─ 已登录 + 有权限 → 放行
  └─ 已登录 + 无权限 → 重定向 /403
```

### Token 持久化与会话恢复

- `localStorage` 键：`duty_access_token` / `duty_refresh_token` / `duty_user_name`
- 页面刷新时 auth store 从 localStorage 读取 token 恢复登录状态
- `main.ts` 启动时调用 `authStore.restoreSession()` 恢复 appStore.userName

### HttpClient 回调配置

```ts
httpClient.configureCallbacks({
  getToken: () => authStore.accessToken || null,
  onUnauthorized: () => {
    authStore.forceLogout()
    router.push({ name: 'login' })
  },
})
```

- `getToken` — 每次 API 请求自动注入 `Authorization: Bearer <token>`
- `onUnauthorized` — 收到 401 响应时自动清除登录状态并跳转登录页

## 说明

- 当前登录后使用前端默认全权限（`ALL_PERMISSIONS`），后续 `M2-P1-T7` 将从后端同步权限。
- Token 未设置过期自动刷新，token 过期后 API 返回 401 → `onUnauthorized` → 自动跳转登录页。
- `forceLogout` 与 `logout` 的区别：`logout` 尝试调用后端接口；`forceLogout` 仅清除本地状态（用于 401 回调中避免二次 API 调用）。
- 页面刷新后从 localStorage 恢复 token，`restoreSession` 仅恢复 UI 状态（用户名），不调用后端验证 token 有效性。
