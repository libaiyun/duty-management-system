# M3-P0-T4 设计修订基础重构说明

## 范围

本任务落实 `docs/design/06-设计修订.md` 中影响已完成 M1-M3 基础能力的关键修订，并作为后续 M3-P2 至 M5 业务开发的前置修复。

## 实现内容

### 当前机房上下文

- 新增后端 `resolve_current_room_id`：普通用户从绑定人员获得所属机房；全局范围用户必须传入 `X-Current-Room-Id`。
- 全局范围用户访问班次定义、人员、排班规则、排班或费用标准时未选择机房，返回 `ADMIN_NO_ROOM_SELECTED`。
- 人员、排班规则和排班的列表、详情、编辑、删除、发布、版本及生成接口均按当前机房过滤；跨机房资源以不存在处理。
- 人员和排班规则创建时忽略请求体中的 `org_unit_id`，强制绑定当前机房。
- 前端保留当前机房 store，并在请求中携带 `X-Current-Room-Id`。

### 班次定义按机房维护

- `shift_def` 增加 `org_unit_id`，并改为 `(org_unit_id, code)` 唯一。
- 班次定义查询、新增、详情、编辑均使用当前机房上下文。
- 班次时间重叠校验限定在同一机房。
- 排班规则网格仅要求当前规则机房启用的班次。

### 费用标准按机房维护

- 新增 `refund_standard` 模型和迁移。
- 节假日仍为全局 `holiday_calendar`。
- 获取某机房费用标准时，自动创建默认标准：早10、中10、晚14、餐补退4、节日加班费150、节日退56。
- 新增 `PUT /api/v1/holidays/standard` 更新当前机房费用标准。
- 节假日与标准前端可编辑当前机房费用标准。

### 菜单与路由

- 菜单入口改为修订后的排班表、换班申请、请假申请、我的顶班、审批中心、排班规则、实际值班、请假记录、退费管理、月度考勤、导出历史等结构。
- 删除排班明细、顶班安排、待办审批/已办审批等独立菜单入口。
- 更新排班规则和排班表路由测试。
- 班次规则与排班规则已拆为独立页面：`ShiftDefView.vue` 仅维护当前机房班次定义，`ShiftRuleView.vue` 仅维护当前机房 N 天循环排班规则。

## 迁移说明

开发数据已清理，全部历史 Alembic 迁移已合并为单一基线迁移
`baseline_20260714_baseline_schema.py`。该基线直接创建当前完整模型、固定角色矩阵、权限和数据范围；`shift_def.org_unit_id` 为非空机房外键。
